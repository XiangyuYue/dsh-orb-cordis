# 悬浮球语音：执行与播报期间接着听

> 对齐日期：2026-10-21。插话在 2026-10-21 修订为「硬停旧轮 + 另起新任务」，见第 3 节。按步骤落地见 [08-voice-listen-plan.md](08-voice-listen-plan.md)。
>
> 与 [05-voice.md](05-voice.md) 冲突时，听法、插话和退下以本文为准。被本文改掉的是 05 的这三处：第 1 节「干活、提问或播报时两路都关」、第 3.1 节「干活和播报时说退下听不到」、第 10 节「不用说话打断正在播的 TTS」。唤醒、空闲时的语音输入、TTS 播什么、播报与执行并行、停止按钮，仍以 05 为准。播报用本地还是千问，见 [09-voice-tts.md](09-voice-tts.md)。听和说不读这一选择，见第 10 节。

语音仍挂在现有悬浮球上。唤醒和语音输入共用同一路麦克风，TTS 只用喇叭。说完一段、静音判定结束后才出整段文字，说的过程中不出逐字稿。转写开着时，进到文字里的只有用户自己的声音，见第 11 节。

## 1. 四段听法

听法由固定、Agent 是否还在执行、正文是否还在播、提问卡是否在等点击决定。鼠标悬停把面板临时展开，不算固定。

| 状态 | 麦克风 | 一句说完之后 |
|---|---|---|
| 没固定，Agent 空闲，正文没在播 | 只听唤醒 | 喊中唤醒词就展开并固定显示框，本地说「我在」。这句不上屏、不发送 |
| 已固定，Agent 空闲，正文没在播，语音输入开着 | 转写开着 | 整句上屏，走现在打字后发送的同一条路径 |
| Agent 正在执行，或 Agent 的正文还在播 | 转写一直开着 | 先认退下口令，再认插话关键词。都没有的句子丢掉 |
| 提问卡在等点击 | 麦克风关掉，转写停掉 | 说话不起作用，在卡片上点 |

「正文还在播」只算这场对话里 Agent 写给用户的正文，包括干活途中那句和收尾。唤醒回复语「我在」、退下回复语「好的，再见」不算。提问提示语「我有几个问题，你来选一下」照旧只出声；它播放的时候提问卡已经在等点击，麦克风是关的。

第三行不看显示框还固不固定。干活途中单击球、固定被取消、显示框因为任务还在先不收时，转写仍按第三行开着。

某一项在设置里关掉，或对应模型还没就绪，05 里那一列就不发生。第三行另外要求语音输入开着、官方 ASR 模型已就绪、插话关键词不是空的。这三样缺任何一样，执行和正文播报期间不听，麦克风按 05 关掉。

从唤醒切到语音输入时麦克风不断开。固定之后立刻说的那句开头留给语音输入。「我在」还在播、转写还没开时，这句听不见。

## 2. 一句怎么判

转写开着时，等整句落地，再按下面的顺序看这一句。落地的这一句只含用户自己说的话，见第 11 节。

已固定且 Agent 空闲、正文没在播：

1. 整句完整带出任意一条退下口令：走第 5 节，不上屏、不发送。
2. 否则：整句上屏并发送。句子里有没有插话关键词都一样，关键词留在原话里。

Agent 正在执行，或正文还在播：

1. 整句完整带出任意一条退下口令：走第 5 节。这一句里同时有插话关键词也只退下。
2. 否则，整句完整带出插话关键词：走第 3 节。
3. 否则：丢掉。不上屏，不发送，不进输入框。

包含按整句匹配：整句就是这条口令或关键词，或长句里完整带出它，都算。只说出其中一段不算。两个字以上的口令和关键词同时接受同音字（不计声调），用户不用另填近似写法。

## 3. 插话

插话关键词出厂是「大肥鱼」。用户说「大肥鱼，你给我把明天的也查一下」，整句带出这个词，就算命中。

上屏和发出去的都是用户原话，关键词留在句子里。显示框里出现一条用户消息，就是这句。

命中的同时，正在播的正文立刻停，队列里还排着的正文清掉。旧任务被强制停掉，和点「停止」相同。旧任务已经写出的正文照常上屏，但不再出声；取消过程中才写完的那部分也不再出声。

这一轮还在跑：立刻中止这一轮，不再等当前工具或这一步结束。等这一轮真正停下以后，把这句原话作为一条新消息发送，另起一轮；不把这句话塞回旧任务，也不走 DeepSeek Harness 的 steer。

正在跑的工具会随取消一起结束。个别工具不响应取消时，新任务要等它结束才能开始；这句原话会先上屏，界面上仍显示旧任务在停。

活已经干完，只剩收尾正文在播：停掉还没播完的声音并清空队列，然后把这句原话上屏，走现在打字后发送的同一条路径，另起一轮。

执行和正文播报期间只要转写开着，输入框上沿的语音指示条就亮着，浅蓝色长条随音量律动。不听的时候隐藏，和现在一样。

## 4. 提问卡

提问卡一出现，麦克风关掉，系统的麦克风指示随之消失，转写停掉。点选、跳过、取消都在卡片上完成。这段时间说退下口令或插话关键词都听不见。

提问提示语该播仍播。用户点选、跳过或取消后，这句还没播完也立刻停，沿用 05。

卡片消失后，按消失当时的状态恢复：

- Agent 还在执行，或正文还在播：回到第 1 节第三行，转写开着，只认退下口令和插话关键词。
- Agent 已空闲，正文没在播，显示框仍固定：回到普通语音输入。
- Agent 已空闲，正文没在播，固定已经取消：只听唤醒。
- 语音输入关着，或官方 ASR 模型还没就绪：不把转写打开。

## 5. 退下

退下口令只要转写开着就生效，不必再带插话关键词。空闲、执行中、正文播报中都算。出厂口令仍是「你退下吧」和「退下吧」，设置里可改多条。一条都不填时，没有退下口令。

整句命中任意一条时，按这个顺序做：

1. Agent 还在执行，就立刻停掉这场执行，和点击「停止」相同。已经空闲就跳过。
2. 正在播的正文立刻停，播到一半也停。队列里排着的正文清掉。
3. 这句话不进输入框，不上屏，不发给 Agent。
4. 取消固定，回到只听唤醒。不主动收回显示框。鼠标不在悬浮球窗口上，就按现有规则收回；鼠标还在上面，显示框留着，等鼠标离开再收回。
5. 再本地说退下回复语，出厂是「好的，再见」。这句只出声，不进对话，也不是 Agent 的回复。先完成第 2 步，再播这句，避免被这次停止清掉。回复语留空，或 TTS 关着，就不说，固定照样取消。

这句回复还在播的时候不听。播完以后显示框已经取消固定，只听唤醒。

转写没开的时候听不见退下。提问卡在等点击时麦克风是关的。唤醒回复语「我在」还在播、转写还没开时，也要等那句说完。

## 6. 设置

主窗口「设置 → 悬浮球」的语音输入这一组里增加一项。

- **插话关键词。** 一条，可改。出厂「大肥鱼」。和唤醒词「你好大肥鱼」是两项，改一个不影响另一个。匹配时自动按拼音容忍同音字，用户不用另填近似写法。留空或只填空白，执行和正文播报期间不听，恢复成 05 的两路都关。空闲时的语音输入不受这项影响。
- **退下口令、退下回复语。** 仍按 05。转写开着时，这两项在执行和播报期间也生效。

官方 ASR 模型不在时，插话关键词和语音输入的开关、退下口令一样不能改，弹窗说明要启动 ASR 语音模型。语音输入开关关掉后，插话关键词不生效。

## 7. 一轮怎么走

下面按唤醒、语音输入、TTS 都开着，三个模型都就绪，插话关键词是「大肥鱼」来写。

1. 球没固定。用户喊「你好大肥鱼」，显示框展开并固定，说「我在」。这句播完才开始听指令。
2. 用户说「查一下今天的天气」。说完后整句上屏并发送。
3. Agent 开始干活。转写继续开着，指示条亮着。用户说「等一下」：没有退下口令，也没有「大肥鱼」，这句话丢掉。
4. 用户说「大肥鱼，把明天的也查一下」。整句上屏并插话。正在播的正文停下，队列清空。这一轮被强制停掉；等它真正停下，这句原话作为新消息发送，另起一轮。
5. Agent 弹出提问卡。麦克风关掉。用户只能在卡片上点。点完、卡片消失后，若活还在干，转写再打开。
6. 用户说「退下吧」。执行停掉，播报停掉，这句话不上屏。显示框取消固定，说「好的，再见」。回复说完后只听唤醒。

收尾还在播、执行已经结束时，用户改说「大肥鱼，再查一次」：收尾停下，这句上屏并作为新的一条消息发送。

## 8. 本文不改的部分

下面仍按 [05-voice.md](05-voice.md) 执行。

- 唤醒词、唤醒回复语、空闲超时取消固定、单击球取消固定。
- 空闲且已固定时，语音输入说完再上屏并发送。下一句不必再唤醒。
- TTS 播哪些正文、不播思考和工具、途中正文赶不上就丢、收尾和提问提示语排队。播报不挡住 Agent 继续执行。
- 显示框上的「停止」：点下去同时停执行、停播报、清队列。
- 唤醒模型和官方 ASR 的准备，以及模型不在时哪些控件不能改。插话关键词的锁定见第 6 节。本地 TTS 的下载仍按 05。选了千问时不必先有这份本地模型，见 [09-voice-tts.md](09-voice-tts.md)。

## 9. 仍然不做

- 用语音回答提问卡。
- 边说边出逐字稿。喊出关键词的那个瞬间不先动作，等整句落地。
- 没有插话关键词、也没有退下口令的句子，在执行和正文播报期间打断播报。
- 把途中没赶上喇叭的正文补播。
- 单独的语音按钮，或另一套 VAD / ASR 参数。

## 10. 播报不绑某一种模型

听法、插话、退下、提问卡和排队，只认播报这一件事：有没有一句正在说，以及能不能立刻停。谁把文字合成成声音，不进入这些规则。

用本地还是千问、密钥放哪、音色和语速，见 [09-voice-tts.md](09-voice-tts.md)。听法、插话、退下、提问卡和排队不读这一选择，也不写死某一种模型的下载方式和合成参数。

换后端时，下面这些保持不变：

- 播什么、什么时候丢、什么时候排队，仍按 05。途中正文、收尾、提问提示语、唤醒回复语、退下回复语，都交给当前选中的那一个后端。
- 一句交给后端之后，到它说完或被停掉之前，都算「正在播」。云端还在合成、喇叭还没出声的这段也算。听法不在这段空档里改口。
- 停止、插话命中、退下，都是立刻停掉正在出的声音，并取消还没合成完的那句。队列按本文和 05 清空。
- 选中的后端还没就绪时，这一列不播，效果与 TTS 开关关掉相同。听法不需要知道它是缺了本地文件，还是云端还没填好。

语音指示条、转写、唤醒词和插话关键词不读 TTS 的模型种类。后端只负责把交给它的那句说出来，并且能被停掉。

## 11. 转写里只有用户的声音

转写开着的整段时间，进到文字里的只有用户自己说的话。Agent 正在执行、正文还在播，也一样。

下面这些声音不进入转写，也不参与退下口令和插话关键词的判定：

- 电脑自己正在放出的声音
- Agent 的 TTS 播报

播报还在进行时，用户一开口就要能听清，用户和播报同时出声也一样。落成的那句是用户说的内容。播报里的词不混进这句，也不单独变成一句用户的话。

用户没说话时，播报和电脑自己的声音不产生转写结果。
